# Repository-first draft contribution reports

October 4, 2026. The owner explicitly requested implementation of the repository dashboard discussed after the installed 0.16.2 checkpoint. This supersedes the earlier instruction to limit this continuation to defect repairs; all accounting, disclosure and preservation boundaries remain.

## Decision

Add a draft analysis layer to the existing modular application. A project accepts up to eight public repository URLs or completed, project-authorized GitHub imports per saved report. Reports need no approved policy or milestone. Public reads use the existing fixed-origin, credential-free, no-redirect transport. Private source continues through the existing GitHub App authority checks. Never borrow the developer's GitHub CLI credentials for application imports.

Persist one-request checkpoints with leases and version checks. Recheck the current caller and original requesting administrator after external reads. Pause by stopping advancement; cancellation fences outstanding responses. Failures require an explicit retry or explicitly incomplete report. Respect recorded backoff across new runs in the project. The browser advances public jobs while the dashboard is open; there is no new unattended privileged worker.

Capture a pinned default-branch SHA, bounded history, reviews, changed-file excerpts and root README/project manifest context. A current tree is context, not a historical checkout. The initial pipeline uses deterministic captured relationships and source-cited excerpts; it does not claim AI semantic understanding or objective completion. Cross-repository repeated commit fingerprints flag possible overlap. Numeric GitHub IDs combine across repositories; email/coauthor claims require explicit identity correction.

Store completed source reports immutably. Store manual entries, identity corrections, unit proposals and the hypothetical amount in separately versioned drafts with append-only revisions. Re-imported changed evidence invalidates an attached proposal. Preserve old reports and reasons. Repository/person display filters retain the project proposal denominator. Manual dates restrict inclusion to the selected report period; project-wide extras remain distinct from repository activity.

Use the versioned `outcome-review-v1` rubric: useful outcome, completion evidence/limitations, relative budget rationale, recipients and overlap. Units are explicitly proposed by a human; activity counts do not assign units. Preserve 1,000 atoms/unit and integer cents. Reuse largest-remainder allocation, including an unassigned recipient so incomplete attribution remains unallocated. No proposed report is approved credit, compensation or a financial close. Display recognized credit separately with its existing policy/pool denominators.

New draft source reports initially remain administrator/reviewer-only, matching the existing raw repository-store boundary. Contributors retain access to explicitly shared evidence and recognized-credit reports. Broader report sharing requires an exact reviewed disclosure step.
