# Maintenance and go-live boundaries

The source is ready for an internal verification cycle, not an unannounced launch. The actual operator decides deployment timing after the technical and human checks; no automatic update, readiness flag, benchmark threshold or model upgrade changes compensation authority.

## First repair priorities

First complete the downloaded dependency installation and real React/Vite build; correct semantic errors with regression coverage. Then execute native PostgreSQL migrations, concurrency and grants, Windows/Docker startup, actual browser workflows and native recovery. These are higher priorities than expanding integrations or adding more scoring dimensions.

Preserve the source version, dependency locks and all applied migrations. Add new migrations rather than changing 0001–0014. Preserve exact financial replay behavior. New discovered models remain unapproved until a prospective profile change. If model/provider behavior changes, freeze affected official runs, preserve history, revalidate with representative authorized cases and record the change.

## Known scope limitations

The product has no objective-worth score, equity issuance, automatic bank transfer, tax filing, public registration or marketplace. Finance is one sequential monthly USD stream and remains synthetic-only. Retrospective grouping is deterministic, not an AI-generated opening balance. Large archive/PDF/game-engine parsing is excluded; supported artifact types and limits remain as documented. Source fragmentation tests do not detect all semantic double claiming.

Partially credited package scope is frozen in this version. Native grants, public-boundary behavior, complete installed dependency scanning and S3 restoration are not proven by mocks. Authenticator and archive cryptography have tests but no independent audit. A trusted unrestricted database/host administrator remains outside the application tamper-resistance boundary.

## Operational ownership before any real deployment

Record privately: operator, backup custodian, incident contact, credential owners, accounting reviewer and independent contribution-review coordinator. Do not invent these people in the source template. Keep incident escalation, credential revocation, source-disclosure containment and restored-environment cutover procedures accessible outside the running application.

Run dependency/advisory reviews on a documented cadence appropriate to the eventual deployment, especially before enabling network access or accepting private evidence. Verify restores rather than merely counting backup files. A security incident or accounting inconsistency blocks closes and new data disclosure until investigated; it does not justify erasing historical records.

Verify source hashes before edits. Keep private configuration and data out of replacement ZIPs. Report new/modified/deleted paths alphabetically and distinguish implemented, actually tested, skipped, and requiring human or external verification.
