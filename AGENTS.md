## Scope and boundaries

Build a Python/FastAPI + PostgreSQL modular backend and React/TypeScript web app. Use manual outcome-based contribution accounting before GitHub and AI automation. Preserve non-code work, versioned policies, independent review, disputes, and exact scoped percentages.

AI may write assessments only. Never give an evaluator ledger-write credentials, money movement tools, arbitrary execution, or secret access. Human approval must be meaningful and tied to the exact reviewed evidence/allocation. Finalized credit and distribution history use linked corrections, not silent edits.

Use integer money and integer unit atoms with exact allocation. Enforce workspace authorization, transactional budgets, and idempotent effects in backend/database code. A UI restriction is not a security boundary. Never run code or install dependencies from a repository being analyzed.

Automatic provider catalogs and approved evaluator profiles are separate. Do not hardcode today's model names or silently choose a new official evaluator. Use permitted customer-controlled credentials locally; public hosted BYOK requires a separate authorization review.

No banking, automatic payments, tax filing, equity issuance, general HR scoring, global reputation, or public signup in the initial release.

## Implementation discipline

Implement the active batch and necessary dependencies only. Keep a runnable tested baseline. Add migrations rather than editing applied ones. Pin compatible dependencies and record changes. Avoid unnecessary new frameworks or scope additions.

Never include .env files, keys, actual private code, uploads, database dumps, node_modules, or virtual environments in source deliveries. Mock external services by default. Do not perform paid requests, public deployment, or real financial actions without the user's explicit authorized setup.
